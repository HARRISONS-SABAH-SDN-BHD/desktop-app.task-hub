NEW IN VERSION 1.2 — AUTOMATIC REPORTING PERIOD
Choose the two raw files. The suffix YYMM sets the period automatically:
ALL_DISC_2610.xlsx and ALL_FTG_2610.xlsx mean October 2026.
ALL_DISC_2701.xlsx and ALL_FTG_2701.xlsx mean January 2027.
The first two digits mean year 2000–2099; the last two are month 01–12.
The detected month/year appear in locked fields, so no period selection is needed.
Both filenames must agree and each file must be in its correct input section.
The raw data's invoice period and document dates are still checked against the
detected period before generation. Filenames do not override conflicting data.
Case-insensitive .xlsx/.xlsm names and download copies such as
ALL_DISC_2610 (1).xlsx are supported. For exports with other filenames, turn
off Detect from filenames (YYMM) and select the period manually.

MANAGE IG NAMES
Click Manage IG names to view the full searchable mapping list. Select an entry
to edit its IG number or agency name and click Update selected. Use New / clear
and Add to insert an entry, or Remove selected to remove one. Click Save mappings
to persist the list. Cancel discards unsaved changes. The next report run uses
the saved names in agency headings and the FTG IG reference sheet.
Removing a mapping never removes transactions. Unmapped agency headings show
IG <number> (unmapped). Restore a mapping to supply the agency name again.
Both settings.json and report_styles.json must remain beside the executable.

START
Double-click Harrison ExcelFlow.exe. No Python installation, Excel installation, internet
connection, or sign-in is needed to use the app. Keep the _internal folder and
settings.json beside the executable. If using the ZIP, extract the entire ZIP
first. Do not run the executable from inside the ZIP preview.

MONTHLY WORKFLOW
1. Browse for the raw DISC workbook, FTG workbook, or both.
2. Check the detected period. The supplied filenames automatically set October
   2026. No month/year selection is required while automatic detection is enabled.
3. Choose Both, DISC or FTG on the main screen. Settings also offers Normal,
   Special or Both report versions. These are independent choices.
4. Select where the results should be saved.
5. Click Validate & preview to review dates and any issues.
6. Click Generate reports. It validates again, then generates the reports.
   You can also click Generate directly; validation is always performed first.
7. Click Open results. Each run has its own folder; earlier runs are retained.

DATE HANDLING
The selected reporting period is authoritative. The app accepts Excel date
values, Excel serial dates, d/m/yyyy, m/d/yyyy, ISO yyyy-mm-dd, and supported
English month names. Common time suffixes are removed during parsing.

Example: select October 2026 and 10/13/2026 00:00:00 becomes 13/10/2026.
An Excel date already interpreted as 10 February 2026 can be recovered as
2 October 2026 when October 2026 is selected and recovery is enabled.

Recovery only swaps the day and month when it produces a valid date in the
selected month and year. It never replaces the year or invents a day. If a date
cannot be resolved to that period, generation stops and lists the source row.
Disable recovery if all typed Excel dates must retain their original meaning.
Text dates are still interpreted using the selected reporting period.

Outputs contain REAL Excel dates with display format d/m/yyyy. The raw inputs
remain unchanged. Two-digit years are rejected to avoid guessing the century.
If a file intentionally contains multiple invoice periods, split it by period
first. Existing invoice month/year columns must agree with your selection.

NUMBERS AND IDENTIFIERS
- IDs are stored as text. Existing text leading zeros are preserved. Numeric
  IDs such as 160.0 become 160. Digits already lost in Excel cannot be recovered.
- Long numeric IDs generate warnings, including unused fallback item IDs.
- Branch code, branch name, abbreviation, or two-digit branch number can map
  to the configured branch. Unknown branches stop processing.
- PGC accepts a whole-number ID or an exactly matching configured agency name.
  Names mapping to multiple PGC IDs require an explicit numeric ID.
- Numeric text such as 1,234.50 and (1,234.50) is supported. Ambiguous comma
  decimals are rejected; use a decimal point. Blank required amounts are errors.
- Quantities retain fractions. PGC/month/year must be whole numbers and are
  never silently rounded. Amount and quantity display precision is adjustable.
- Amount display settings do not round the underlying source amounts. Quantity
  settings can hide additional decimal places on screen; full values remain.
- The P160 second discount uses the multiplier (default 0.88), rounded per row
  with decimal half-up rounding to the selected amount precision. A half-cent
  tie can differ from the old scripts' binary-float rounding.
- Names are trimmed, not guessed or fuzzy-matched. Product names are not used
  to invent item IDs. Missing item numbers use item_id according to the PGC
  fallback rule inherited from the original scripts.

REPORT RULES
Normal DISC: retain IPCD and N/A/missing promotions.
Normal FTG:  retain IPCF and N/A/missing promotions.
Special DISC: retain IPCF only.
Special FTG:  retain IPCD only.

Each branch gets a workbook, a main sheet and a sheet for each PGC present.
FTG workbooks also include the IG agency reference sheet. Special output may
legitimately omit a branch or FTG altogether if no transactions match.

DISC discount signs follow gross amount when gross is nonzero. FTG discount,
free quantity and free amount signs follow invoice quantity. P160 second
discount values are calculated in both main sheets and P160 sheets.

IMPROVEMENTS TO THE OLD REPORTS
- Correct branch labels on agency sheets (fixes Branch : None).
- Consistent row-7 headers and freeze panes; filterable main/PGC sheets.
- Real Excel dates, text IDs, numeric amounts, and fractional quantities.
- P160 second-discount values also populated on the DISC main sheet.

  and may wait for the current workbook save to finish.

VALIDATION AND OUTPUTS
Validation errors stop report generation; inspect the Issues tab and the
validation_issues.csv saved in a Validation folder. Only the first 500 issues
are displayed in the app; the CSV includes all. Warnings permit generation
and are saved in the run folder. Date preview shows a sample, not every row.
run_summary.json records period, conversion counts, output row counts,
totals, selected precision, multiplier, sources, and completion status.
Cancelled/failed runs may contain a partial set of reports and are marked
accordingly in their summary. Use complete runs for reporting.

MAPPINGS AND INPUT LAYOUT
Manage IG names opens the in-app agency mapping editor. Branch and header
mappings remain in settings.json. The app reloads mappings for each action.
Additional header aliases can be supplied under column_aliases, for example:
  "column_aliases": { "date": ["Transaction Date", "Document Date"] }
Use unique exact aliases. No changes are made to the original spreadsheets.
The data must have headers in row 1, on exactly one recognizable data sheet.
Additional unused source columns are ignored and listed in run_summary.json.
Formulas in recognized raw columns are rejected: export their values instead.
Supported formats: .xlsx and .xlsm (macros are neither run nor copied).
Legacy .xls must first be saved/exported as .xlsx.
